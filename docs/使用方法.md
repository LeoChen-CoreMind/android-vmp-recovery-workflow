# Android 某6零免费版 DexVMP 恢复工作流：使用方法

本文用于在本地搭建 Android 某6零 DexVMP 学习研究环境，并按仓库提示词执行一个可追溯的案件。所有输入、输出和日志都留在本机。

> **仅限学习研究**：只分析自有或获得明确授权的 APK、DEX、SO 和设备。本文不承诺对任意版本、任意厂商保护或业务校验有效，也不应被用于盗版、绕过商业授权或未授权修改第三方软件。

> **范围限制**：本文仅针对某6零免费版样本的学习研究和授权分析。付费版、商业版及其专属保护方案不提供样本、参数、适配、还原服务或技术支持，相关请求不受理。

## 一、环境要求

### 主机环境

- Windows PowerShell
- Python 3.10 或更高版本，命令使用 `py -3`
- Git
- Android SDK Platform-Tools（提供 `adb`）
- Android SDK Build Tools（提供 `aapt2`、`zipalign`、`apksigner`、`dexdump`）
- Apktool（用于 APK 解码、smali 检查和按当前版本证据重建 APK）
- Java 运行时（JADX 默认反编译需要）
- JADX 命令行或可执行文件，并确保能从 `PATH` 调用
- SoFixer（按本地配置提供）
- Frida 主机工具 17.9.1
- IDA Pro 与可用的 IDA Pro MCP 服务
- Unicorn Python 依赖（项目环境安装）

先检查基础工具：

```powershell
py -3 .\vmpwf.py doctor
adb version
java -version
jadx --version
frida --version
where.exe adb
where.exe jadx
where.exe java
```

`doctor` 报告缺少工具时，先修复本机 `PATH` 或项目配置，再开始案件。JADX、IDA Pro MCP、dexdump 的真实退出码和日志会写入案件报告，不能用“看起来能打开”代替验收。

### Apktool 安装建议

从 Apktool 官方发行版获取 `apktool.jar` 和 Windows 包装脚本，放置到例如 `C:\Tools\apktool`，将该目录加入当前用户 `PATH`。确认命令可用：

```powershell
apktool --version
apktool empty-framework-dir --force
```

重打包阶段使用 Apktool 解码和构建当前案件 APK；Manifest、smali、DEX 映射和壳资产必须由当前 APK 的 inventory 与证据确定，不能按文件名关键词批量删除。

### JADX 安装建议

从 JADX 官方发行版获取 Windows 压缩包，解压到例如 `C:\Tools\jadx`，将 `C:\Tools\jadx\bin` 加入当前用户 `PATH`，重新打开 PowerShell 后确认：

```powershell
jadx --version
jadx-gui --version
```

JADX 运行需要 Java。命令行验收使用 `jadx`，不要只验证 GUI 能否启动；案件报告必须保留实际退出码、标准输出和错误输出。

### IDA Pro MCP

IDA Pro MCP 必须能打开案件当前 revision 的 `fix/so/rev-*/*_fixed.so`，并返回结构化 JSON。分析前需要确认：

1. MCP 服务可连接，健康检查指向当前案件文件。
2. 输入 SO 的 SHA-256 与 `so-repair` 记录一致。
3. 能读取反汇编、函数、交叉引用和指针槽，并生成包含 256 个 opcode 的响应。
4. `image_base` 和运行时 `pointer_base` 分开填写，不能把 ASLR 地址当作静态 RVA。

IDA Pro 和 MCP 服务属于本地外部环境，仓库不包含商业软件或 MCP 服务端。请按所使用的 MCP 实现完成 IDA 插件/服务配置，并在 AI 助手侧确认健康检查、反汇编读取、函数查询、交叉引用查询和 JSON 响应生成均可用。MCP 服务只接收当前案件的 fixed SO 和证据路径，不要上传客户文件到第三方服务。

IDA 只负责当前 SO 的证据提取；不要复制其他 APK、旧版本或 fixture 的 root RVA、handler 含义、宽度和模拟常量。

### 真机、ADB 与 root

设备必须满足：

- `adb devices` 显示唯一在线设备；
- 目标 APK 已安装，包名、版本和 ABI 与案件输入一致；
- `adb shell su -c id` 能返回 `uid=0(root)`，或 `adbd` 本身具备 root；
- 目标为 ARM64，符合 `android-arm64-360-dexvmp` profile；
- 允许本机部署 profile 自带的 `tools/frida/media-server`。

检查命令：

```powershell
adb devices -l
adb shell getprop ro.product.cpu.abilist
adb shell su -c id
adb shell pm path <package.name>
```

设备重启会使 root 服务端和 Frida 会话失效。每次重启后都要重新准备 `media-server`，不能复用旧会话。

## 二、准备输入

至少准备一个 APK；如果有运行时 dump 的 DEX ZIP 或 `classes*.dex` 目录，也一并登记。输入文件必须是绝对路径，框架会记录大小和 SHA-256。

```text
APK：C:\research\target.apk
DEX ZIP：C:\research\runtime-dex.zip（没有则填 null）
DEX 目录：null（或 classes*.dex 所在目录）
设备序列号：<adb devices 中的 serial>
已有案件目录：null（新案件）
```

不要把客户 APK、DEX、SO、IDA 数据库或日志提交到 Git。案件证据默认写入 `cases/<package>/<case-id>/`。

## 三、启动工作流

进入仓库目录后先运行：

```powershell
py -3 .\vmpwf.py doctor
```

仅 APK：

```powershell
py -3 .\vmpwf.py recover `
  --apk "C:\research\target.apk" `
  --profile android-arm64-360-dexvmp
```

APK 加 DEX ZIP：

```powershell
py -3 .\vmpwf.py recover `
  --apk "C:\research\target.apk" `
  --dex-zip "C:\research\runtime-dex.zip" `
  --profile android-arm64-360-dexvmp
```

APK 加 DEX 目录：

```powershell
py -3 .\vmpwf.py recover `
  --apk "C:\research\target.apk" `
  --dex-dir "C:\research\runtime-dex" `
  --profile android-arm64-360-dexvmp
```

`recover` 完成输入登记和前置阶段后，读取命令输出给出的案件目录，再执行真实设备阶段：

```powershell
py -3 .\vmpwf.py run `
  --case ".\cases\<package>\<case-id>" `
  --execute-device
```

## 四、阶段和原理

### 1. APK/DEX ingest

框架检查 APK Manifest、包名、ABI、DEX 列表并建立不可变输入副本。运行时 DEX 只能作为输入证据，不能因为 checksum 正确就直接标记为 VMP 已恢复。

### 2. target-confirm

通过 ADB 确认包名、版本、UID、安装路径、ABI、SELinux 和 root 能力。目标不匹配或 ABI 不符合 profile 时停止。

### 3. SO dump

`run_gating.py` 先校验并启动 hash 固定的 `media-server`，再启用 Frida spawn-gating，在目标进程恢复执行前加载 agent。采集目标构建的私有 `soinfo`、`loadStart`、`loadSize`、program headers 和动态表证据。普通外层 `libjiagu` 映射或 APK 资产副本不算私有 linker dump。

### 4. SO repair 与 IDA Pro MCP

SoFixer 只处理当前案件的私有 linker dump。修复后检查 ELF、PT_LOAD、PT_DYNAMIC、动态标签和符号证据。IDA Pro MCP 对 exact fixed SO 导出当前 dispatcher/handler 表，必须覆盖 256 个 opcode。

### 5. Unicorn 原生确认

使用 `scripts/simulation/run_native_confirmation.py` 和同一份 fixed SO 执行真实 AArch64 dispatcher 路径。要求 256/256 匹配、零 mismatch、零非法内存、零未知外部调用，并绑定 SO、IDA 响应和配置哈希。

### 6. DEX 方法恢复

先检查 LM/VMP inventory。只有 `method_records > 0` 才进入方法流恢复；每个方法都必须满足引用合法、opcode 完整、指令宽度闭合、最终 PC 等于 `insns_size` 且 code unit 数量可回写。若记录数为 0，只能明确报告“本案没有可恢复的 VMP 方法”。

### 7. 独立验收与重打包

恢复 DEX 后由独立验证阶段检查 header、SHA-1、Adler-32、map、manifest 覆盖，并运行 Android `dexdump` 和 Java-backed JADX。真实某6零案件随后按当前 APK/revision 生成 adapter，精确处理壳 SO/资产、DEX 映射、Manifest、Stub 调用和签名，再运行 `aapt2`、`dexdump`、JADX、`zipalign`、`apksigner`，必要时进行设备冷启动验收。

## 五、查看状态与恢复 BLOCKED

常用命令：

```powershell
py -3 .\vmpwf.py status --case ".\cases\<package>\<case-id>"
py -3 .\vmpwf.py plan --case ".\cases\<package>\<case-id>"
py -3 .\vmpwf.py validate --case ".\cases\<package>\<case-id>"
```

每个案件都要保留并检查：`case.json`、`checkpoint.json`、`questions.json`、`events.jsonl`、`artifacts.json`。如果出现 `BLOCKED`，先读取 `prompts/hot_update_operator_zh.md`，根据问题中的证据准备最小 JSON 答案：

```powershell
py -3 .\vmpwf.py resume `
  --case ".\cases\<package>\<case-id>" `
  --question q-0001 `
  --answer ".\answer.json"
```

不要手工编辑 checkpoint、question 或 stage record。`resume` 会增加 `config_revision`、归档失效阶段并从正确边界继续。

## 六、结果判定

最终报告必须分别说明：

- 哪些阶段已通过、哪些未执行或不适用；
- APK、DEX、SO、IDA 响应和 simulation 的 SHA-256；
- 是否真的恢复了 VMP 方法以及数量；
- dexdump、JADX、aapt2、zipalign、apksigner 的真实退出码；
- adapter、重打包 APK、签名和设备验收结果；
- 仍未解决的业务校验、崩溃或环境问题。

“能安装”“出现首屏”或 fixture 成功，都不能单独证明当前 APK 已完成 VMP 恢复。

## 七、完整提示词

自动化执行时，使用仓库内的[本地全自动操作提示词](../prompts/local_autonomous_operator_zh.md)，把其中的框架目录、APK、DEX、设备序列号和案件目录替换成当前实际路径。提示词要求全程本地执行、证据驱动、遇到不确定事实立即阻塞，不允许猜测参数。

可直接把下面的启动模板交给支持本地文件、命令执行和 IDA Pro MCP 的 AI 编程助手：

```text
请读取并严格执行：
C:\Users\Rabe\Desktop\222\android-vmp-recovery-workflow\prompts\local_autonomous_operator_zh.md

框架目录：
C:\Users\Rabe\Desktop\222\android-vmp-recovery-workflow

本次输入：
- APK：C:\research\target.apk
- DEX ZIP：null
- DEX 目录：null
- 设备序列号：null
- 已有案件目录：null

请全程在本地使用 vmpwf、ADB/su、Frida、SoFixer、IDA Pro MCP、Unicorn、Java、dexdump 和 JADX 执行。
所有结论必须有命令输出、设备信息、日志、反汇编、JSON 或 SHA-256 证据。
遇到未知偏移、多个候选、证据冲突、工具缺失或需要作者决定的事项时，按提示词规定的 BLOCKED 格式暂停并提问；不要猜测，也不要复用其他 APK、旧案件或 fixture 的参数。
```

如果已经有运行时 DEX，把 `DEX ZIP` 或 `DEX 目录` 中的一项改成绝对路径；继续旧案件时填写原 APK/DEX 路径和 `已有案件目录`，以便框架核对 provenance。
